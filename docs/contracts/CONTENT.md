# Content contract v1, provisional

Root owns this contract. One content JSON document has id, title, version, start (scene ID), scenes (array). Scene: id, title, paragraphs (string[]), choices (array). Optional scene requires (string[]). Choice: id, label, target (scene ID), optional requires (string[]), unless (string[]), effects (string[]), observation ({id,text}), interpretation ({id,text}), relationship ({id,text}), ending (boolean). Optional scene variants: array of {requires: string[], paragraphs: string[]}; select the last matching variant. Base paragraphs remain source text; engine captures the rendered paragraphs in transcript entries on entry. All requirements require all listed flags. Choice flags are applied before target rendering. Effects only add flags, no hidden randomness or score.

Choices perform exactly the action stated in their label. Observations store facts as encountered, interpretations store player-selected readings, relationships store interpersonal decisions. Reinterpretation never edits old observations or transcript entries. Player export contains encountered material and state only, never the full content document or unseen nodes. All bundled offline static content is inspectable by technically knowledgeable users; secrecy at source-code level is not claimed.

Pure engine functions validateContent(unknown), createGame(content), applyChoice(content,state,{id,choiceId,expectedRevision}), availableChoices(content,state). Exact exported API may be coordinated by engineer in ENGINE-API.md. Immutable states include contentId, contentVersion, revision, currentScene, flags, observations, interpretations, relationships, transcript and processed command IDs. Duplicate command IDs are no-ops; stale expectedRevision is an explicit conflict. Never silently apply a stale tab's move. Engine verifies eligibility and target; content graph validates IDs, links and requirements.

Save envelope uses explicit version and validated state; IndexedDB persistence must report corruption, quota failure and stale saves without losing the active in-memory game. Restore validation cannot trust imported JSON. Keep a last good checkpoint where possible. Tests use fake IndexedDB and meaningful paths.

Author view edits/imports/exports this same JSON format, validates before applying, labels spoilers, and is separate from the player view. No elaborate authoring platform required. Keyboard operable choices, visible focus, polite passage announcements, reader-sized text and reduced-motion support.
